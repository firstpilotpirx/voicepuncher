## Why

Each speech recognition service (dictation on port 8081, commands on port 8085) runs as three copies of `whisper-server` behind HAProxy, so that one long dictation chunk does not block a short command confirmation and a dead copy gets no requests. HAProxy is a fifth process the user installs with Homebrew, a config the `justfile` generates (`haproxy_config`: leastconn, maxconn 1 per copy, a priority class for short audio, abortonclose, health checks every second), and a supervisor of its own. The application is becoming a self-contained bundle that starts its own services (`local-services-runtime`) and is installed from a DMG with no Homebrew (`app-bundle-and-dmg`, `bundled-engines`): HAProxy cannot come along, and bundling a load balancer for three loopback ports is wrong anyway. The routing is a few dozen lines of Rust: a request takes a free copy or waits; a copy whose port does not answer is skipped; an abandoned request must not hold a copy. The user asked that this routing be separated from the dictation logic into the component that will manage the services, shared with the command spotting service, which confirms utterances against the commands service.

## What Changes

- HAProxy is gone. `just start-model-servers` starts the copies of each speech recognition service on the ports it already computes for them — base port + 10000 + copy number: dictation 8081 → 18082, 18083, 18084; commands 8085 → 18086, 18087, 18088; the test ports 28081 → 38082–38084 and 28085 → 38086–38088 (when base + 10000 + copies would pass 65535 the `justfile` already uses base − 10000; the convention keeps that rule) — and nothing listens on the base port when there is more than one copy. With one copy (`VOICEPUNCHER_STT_INSTANCES=1`), the copy listens on the base port itself. `just stop-model-servers` stops the copies; the HAProxy config, the `haproxy` binary requirement and the README's `brew install haproxy` go away.
- The app and the command spotting service find the copies by that convention from the configured service address (`[transcription] base_url`, `--transcription-url` of the command spotting service): they probe the base port and the copy ports (base + 10000 + 1 … + 4); when the base port accepts a connection it is the one copy, otherwise every copy port that accepts a connection is a copy of the service. A copy that stops answering leaves the pool at the first refused connection and comes back when it answers again (probed every second, like HAProxy's `check inter 1s fall 2 rise 1`). A copy that appears later (the `justfile` started it after the app) joins within a second.
- A request takes a free copy or waits its turn (first come, first served), never two requests on one copy at once (whisper-server processes one inference at a time; a second request would queue inside it with no visibility). A request that cannot connect to its copy is retried on another copy, up to 3 more times (HAProxy's `retries 3`, `redispatch`). A request whose caller gives up (its timeout passed) releases nothing until the copy answers it: the copy is marked draining and gets no new request until the server's answer arrives (or the copy is restarted by its supervisor), so an abandoned confirmation never delays the next one — the "A request given up by its client does not hold a copy" requirement, without `abortonclose`.
- A copy that takes longer than twice the request timeout is reported hung (`speech recognition copy 18083 hung: no answer in 120 s`) and leaves the pool until it answers again; restarting it stays the supervisor's job (the `justfile` health watcher today, `local-services-runtime` later), as the spec requirement "A service that stops answering is started again" says.
- Dictation: the app's transcription client uses the pool of the dictation service; the live worker sends the chunks of a recording one after another, as it does today (one client, one request at a time), so for dictation the copies give resilience — a chunk whose copy died is retried on another — not parallelism. Every client of one process shares one pool per service address (a registry keyed by the address), so several clients in one process (the E2E steps that send nine requests at once) spread over the copies instead of all taking the first one; and each process starts its search for a free copy at an offset of its own (derived from its process id), so two processes sent against the same service (the accuracy benchmark runs two app processes at once) usually take different copies without talking to each other. Voice control: the command spotting service holds one pool for the commands service; a confirmation takes a free copy or waits until its confirmation deadline (3 s) and is then given up without ever holding a copy, so confirmations do not pile up (the existing requirement).
- The "Short speech is transcribed ahead of long speech" requirement is removed from the `local-services` spec: since `commands-service` gave commands a speech recognition service of their own, no short confirmation shares a queue with a long dictation chunk, and the priority class is dead configuration.
- The requirement "The speech recognition service runs as several copies behind one address" changes to "runs as several copies found from its address" (the convention above), and "Stopping the speech recognition service stops every copy" keeps its meaning without HAProxy.
- E2E scenarios that start their own speech recognition services (`@local_services`, `@resilience` steps) pick base ports whose copy ports are free (past port 65531 the copies sit 10000 below), start the copies on the convention ports, and keep passing; the resilience scenarios (a copy paused, killed, restarted while voice control runs) now exercise the pool instead of HAProxy.
- The shared code is a new workspace crate `copy-pool/` (package `voicepuncher-copy-pool`, plain Rust, dependencies `log` only), used by the app's transcription adapter and by the command spotting service's confirmation client. In the app it is reached only from adapters; the local services component (`local-services-runtime`) will later hand it the exact copy list it started instead of probing.
- `docs/architecture/overview.md` (HAProxy mentions, the services table), `README.md` § Local services, `docs/ubiquitous-language.md` (Copy, Copy pool, Lease, Draining copy), the tech matrix (agent-kit PR, section "macOS Desktop": service copies routed by an in-process pool crate; HAProxy removed).

Current stage: PoC. Target stage: Prototype (no third-party proxy; the routing is owned, tested code).
Scope: the `copy-pool` crate; its use in the dictation transcription adapter and in the command spotting confirmation client; the `justfile` without HAProxy; README and docs; the `local-services` spec deltas; E2E steps for own services.
Acceptance bar: `just full-check` passes with the WER accuracy on 100 recordings (the recognition path changed) and the E2E resilience and seams suites green; a 2-minute dictation with 3 copies transcribes every chunk, one after another as today, with the copy's port in the debug log of each request; a voice command is confirmed while a long dictation chunk is being recognized; killing one copy during a dictation loses no chunk (retried on another copy); no `haproxy` process runs; the user pastes a healthy log of a manual run with voice control.
Out of scope: sending the chunks of one dictation to several copies at once (the live worker stays sequential; a later change if the wait after the last chunk matters); starting or restarting the copies from the app (`local-services-runtime`); changing whisper-server's flags, models or the chunking; the text refinement service (one llama-server, no copies); a pool for the command spotting service itself (one process).

## Capabilities

### Modified Capabilities

- `local-services`: copies are found from the service address by the port convention, not behind a proxy address; "Short speech is transcribed ahead of long speech" is removed; "A request given up by its client does not hold a copy" is kept with the draining mechanism; "A copy that stops does not stop the service", "Stopping the speech recognition service stops every copy", "Several copies that cannot start are reported and leave nothing behind", "The command spotting service does not pile up confirmations", "Speech that is no command is confirmed quickly" keep their meaning without HAProxy.
- `speech-recognition`: a dictation chunk is sent to a free copy or waits; a chunk whose copy dies is retried on another; a hung copy is reported.
- `voice-control`: a confirmation takes a free copy of the commands service or waits until its deadline.

## Requirements to specify

1. Copies are found from the service address: given a service address with port P, P is the one copy when it accepts a connection, otherwise every port among P + 10001 … P + 10004 that accepts a connection is a copy; a copy that stops answering leaves the pool at its first refused connection; one that answers again, or a new one, joins within a second.
2. A request takes a free copy or waits: with every copy busy a request waits, first come first served, and starts on the first copy that frees; no copy handles two requests at once.
3. A request whose copy died is retried on another copy, up to three more times; when every try fails the request fails with the copies named.
4. A request given up by its client does not hold a copy: a copy still answering an abandoned request gets no new request until that answer arrives; the next request goes to another copy or waits.
5. A copy that does not answer in twice the request timeout is reported hung and gets no requests until it answers again.
6. A confirmation never waits past its deadline: a confirmation of the command spotting service that finds no free copy by its deadline is given up without holding a copy.
7. (removed) Short speech is transcribed ahead of long speech.

## Implementation guide

1. **Crate.** `copy-pool/Cargo.toml` (package `voicepuncher-copy-pool`, edition 2021, `log`), `copy-pool/src/lib.rs`: `CopyPool::shared(base_url) -> Arc<CopyPool>` (one pool per process per address, from a registry; `CopyPool::discover(base_url, probe)` builds one for a test) (base URL with scheme, host, port, path; copies get the same scheme, host and path with their port), `pool.lease(wait: Duration) -> Result<Lease, PoolError::NoFreeCopy | NoCopies>`, `Lease::url(&self) -> &Url`, `Lease::finished(self)` (the normal release), `Lease::abandoned(self)` (the copy becomes draining; a probe thread marks it free again when the copy's inference finishes: because whisper-server answers a TCP connect even while busy, draining ends when the abandoned HTTP response is finally read by a background reader, which the lease holder hands over: `Lease::abandoned_with(self, pending: Box<dyn FnOnce() + Send>)` that runs the blocking read to the end on a pool thread, then frees the copy), `pool.report_hung(lease)`, `pool.snapshot()` for logs and the menu. Internals: a `Mutex<State>` + `Condvar` for waiting; the search for a free copy starts at a per-process offset (process id modulo the copies) and goes round, so two processes against the same service usually take different copies; a probe thread (1 s) that TCP-connects every candidate port with a 200 ms timeout and updates up/down; a `Probe` trait (`fn answers(&self, addr) -> bool`) injected for tests with a fake. The crate has no HTTP code: the adapter does the request with ureq and tells the pool what happened.
2. **App adapter.** `adapters/secondary/transcription/openai/mod.rs` (`OpenAiTranscriber`): `connect` builds the pool from `cfg.base_url` (fails as today when no copy answers: "speech recognition service at URL does not answer"); `transcribe` takes a lease (wait = the request deadline), posts to the lease's URL with the existing `post_with_retries` changed to take a new lease on a connection failure (3 more tries after a dropped connection), calls `finished` on an answer, `abandoned_with` on a timeout (handing the response reader over), `report_hung` after twice the timeout. The live chunk worker (`run_live_worker`) keeps sending the chunks one after another (design D3b). Log line per request: `stt copy 18083 took 1234 ms` at debug.
3. **Command spotting.** `command-spotting/src/confirm.rs` (`UtteranceTranscriber`): build the pool from `--transcription-url`; `hear` takes a lease with wait = the confirmation deadline minus the time already spent; `NoFreeCopy` by the deadline → the confirmation is given up (the engine already handles a timed-out confirmation; keep that path). The `health.rs` stuck detection stays.
4. **justfile.** `start_whisper`: remove the HAProxy branch, keep the copy ports computation, start the copies with `start_service` as now, write the `.copies` list, no frontend; `stop_whisper`/`stop-model-servers`: stop the copies from the list; delete `haproxy_config`, `require_binary haproxy`; `start-model-servers` prints `✓ dictation service: 3 copies on 18082-18084` and the base port as the service address. The readiness of the service = every copy answers; `port_open` on the base port is no longer the "already running" check: check the copy ports (or the base port with one copy).
5. **Tests.** Unit tests in the crate: discovery with a fake probe; lease/wait/free; FIFO; a down copy skipped; a copy coming back; abandoned → draining → free after the pending reader ends; hung reported. Adapter integration `app/tests/transcription_openai_it.rs`: two tiny HTTP servers (threads with `std::net::TcpListener`, answering the transcription JSON after a delay) on convention ports of a free base; two chunks run in parallel, one per copy; a server closed mid-test → the chunk is retried on the other. Command spotting: unit test of the deadline wait. E2E: `@resilience` suite as is (`just e2e-resilience`), `@seams` as is; the steps that start own services (`e2e-test/tests/steps/` for `@local_services`) start copies on the convention ports.
6. **Docs.** README (install: no HAProxy; local services table: copies and their ports; how to run one copy), `docs/architecture/overview.md`, `docs/ubiquitous-language.md`, `docs/project-map.md` (`copy-pool/`), the `justfile` comment that explains the port convention; the agent-kit tech matrix PR; add `copy-pool/` to `recognition_paths` in the `justfile` (so `full-check` runs 100 recordings for changes to it).

Pitfalls: the base port is probed first and, when it answers, it is the only copy (a single copy on the base port and three copies on the convention ports never coexist; should both answer, the base port alone is taken); the pool must not be built in `core` (architecture test: `core` imports no workspace crate besides anyhow/thiserror/serde/log — add `voicepuncher_copy_pool` to the forbidden list for `src/core`); ureq's `timeout` closes the socket on expiry, so the "pending reader" of an abandoned request must be a separate request object whose reader continues — implement abandonment as: the request thread itself keeps reading after the caller stopped waiting (the caller waits on a channel with the deadline; the request thread finishes and frees the copy), which makes `abandoned_with` unnecessary: prefer this simpler form; the probe must use a short connect timeout (200 ms) so a 1 s cycle covers 5 ports.

## Open points

- Probe range: P + 10001 … P + 10004 (up to 4 copies, so the copies of dictation on 8081 stay apart from those of commands on 8085) and P; alternative: a `copies` count in the config (rejected: discovery needs no config and matches the `justfile` which already knows the count).
- Whether an abandoned request's copy should be marked draining (proposed) or the pool should simply prefer other copies (simpler, less exact): proposed draining, implemented by letting the request thread finish reading.
- Hung threshold: proposed twice the request timeout (dictation: 2 × `timeout_secs`; confirmations: 2 × 3 s).
