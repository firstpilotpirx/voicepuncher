# Tasks

No Rust code changes and no spec scenario (`skip_specs: true`): each behavior is checked by running the recipes (design.md § Test levels). Where it means something, a Red item first shows today's behavior or a failing stub, then the Green item implements the behavior and runs its check. Scratch edits and throwaway commits are never pushed. Every check runs through `just` recipes. In a worktree, set `VOICEPUNCHER_BENCH_CORPUS` to the main checkout's `e2e-test/corpus` for every run below.

"`just check` passes" and "`just full-check` passes" below allow, as the proposal's acceptance bar does, a failure that another filed change owns, named in the PR. Two are known (`research/README.md`): `voice_forms_it` on the user's session-2 "restart" at 27.23 s (`recognize-users-quiet-restart`; the same on `origin/main`), which ends `e2e-smoke` before `voice_samples_it`, `placed_commands_it` and the `@smoke` scenarios run, and 7 `@seams` scenarios "Long speech under difficult recording conditions" (`raise-accuracy-under-hard-conditions`), which end `e2e-seams`. The stages after such a failure then run on their own (`just _stages <the rest>`); with `VOICEPUNCHER_VOICE_SAMPLES` at a copy of the user's recordings without that one "restart", `e2e-smoke` runs to its end, as in the measurements of group 7.

Dependency (design.md § Dependencies): this change starts only once `test-without-machine-lock` is on `main`; group 1 builds on its device, `with-machine-lock` with a `MACHINE_LOCK_DIR` of the run's own. `fail-hung-tests-fast` is no dependency.
