## Context

See proposal.md — Why. The proposal's paths predate the move of the integration tests into one `it` binary per member: the gated tests now live in `app/tests/it/*.rs`, `app/tests/main_thread/*.rs` (a `harness = false` binary that lists `<module>::<name>` to nextest), `command-spotting/tests/it/*.rs` and `e2e-test/tests/it/hang_probe.rs`. The pipeline tests the proposal names were already rewritten by `slim-pipeline-module`; the ones still without a check are found by the new architecture rule (D4). Recipes pick tests with nextest filtersets (`_test-filter`, `_smoke-part-filter`, `_it-filter`), already ANDed with the frozen list.

## Goals / Non-Goals

**Goals:** a missing need is a counted skip in the recipe, never a green test; the desktop tests run in `full-check` when the permissions allow; every test checks something; the paste tests never touch the user's clipboard; a step text both harnesses use lives once.
**Non-Goals:** accuracy thresholds (`tighten-accuracy-gates`); spec mirroring (`mirror-specs-in-features`); the cucumber tag gates of `scenario_filter` (`@voice_samples`, `@real_keyboard`, `@signing_identity`), which already leave scenarios out and print one `GATED:` line per closed gate.

## Decisions

**D1 — A need is a module name; the recipe filters by it.** A test that needs something lives in an inline module named after the need, so its nextest name carries it: `needs_stt` (`VOICEPUNCHER_TRANSCRIPTION_URL`), `needs_command_stt` (`VOICEPUNCHER_COMMAND_TRANSCRIPTION_URL`), `needs_kws` (`VOICEPUNCHER_COMMAND_SPOTTING_URL`), `needs_kws_models` (`VOICEPUNCHER_KWS_MODEL_DIR` and `VOICEPUNCHER_KWS_VAD_MODEL`), `needs_voice_samples` (`VOICEPUNCHER_VOICE_SAMPLES`), `needs_corpus` (`$VOICEPUNCHER_BENCH_CORPUS/manifest.jsonl`), `needs_desktop` (`VOICEPUNCHER_DESKTOP_IT`, D3), `needs_hang_probe` (`VOICEPUNCHER_HANG_PROBE`). A test with two needs nests the modules. In the `main_thread` harness the listed name carries the module the same way (`settings_macos::needs_desktop::should_…`). Rejected: a list of test names per need in the `justfile` (a test missing from it is silently unfiltered); nextest `default-filter` (one per profile, no condition on the environment).

**D2 — `_gates` computes the exclusion and prints the count.** One recipe holds the table need → condition → reason. For the current environment it prints a nextest filterset `not (test(/::needs_a::/) | …)` of the closed needs and, on stderr, one line per closed need with a test in the selection: `● skipped N test(s): <need> — <reason>`, N from `cargo nextest list` with the caller's targets and filter (the binaries are built by then). `_test-filter`, `_smoke-part-filter` and `_it-filter` AND it in, like the frozen filter, and the recipes that run them print its lines before nextest runs. A test that runs with its need missing fails: the shared `required_env` (D6) panics naming the variable and the recipe that sets it. `test` therefore never runs a service test, and a smoke part without the user's recordings prints the count of the recording tests it left out.

**D3 — The desktop tests: stage `it-real`, alone on the machine, behind `_require-tcc`.** The tests on the real microphone (`recording_cpal`, including the default input device), the Accessibility API (`focus_macos`) and windows on screen (`menubar_macos`, `settings_macos`) move into `needs_desktop`. `just it-real` runs them through `_stages it-real`; the stage is a model stage (classified like `e2e*`), so it runs in the exclusive phase with the machine alone — it takes the screen and the microphone — and starts no service it does not need (it is added to the `own_services` list). `full-check` runs it before `e2e-cues`. `_it-real` first runs `_require-tcc`: a small binary of `e2e-test` (`tcc-probe`) asks the app's `MacOsPermissionProbe` for Microphone and Accessibility and prints each one missing with the responsible app; when one is missing the stage prints it, prints the count of desktop tests left out and exits 77. `_model-stages` and `_stages` show exit 77 as `–` skipped in the table, journal it `skipped`, record no pass and go on. `AGENTS.md` § How to verify a change adds `just it-real` to the manual run for that case. The real-keyboard test (`keypressing_macos`) presses Return, Cmd+A and Backspace in the focused app, which would erase the user's text during a check: it moves into `needs_real_keyboard` (`VOICEPUNCHER_REAL_KEYBOARD_IT`) and runs only in the manual `test-real-keyboard` recipe, which now also runs it. The settings snapshot (`should_draw_every_tab`) draws into a temporary folder when `VOICEPUNCHER_SETTINGS_SNAPSHOT` is unset and checks that every tab's PNG was written and is not empty; it needs no window on screen. Rejected: running `it-real` among the build stages (the windows would sit beside another run's model stages and its cue timing).

**D4 — The architecture rule.** `app/tests/it/architecture.rs` gains `test_checks`: it scans every `.rs` file of the four members for `#[test]` / `#[tokio::test]` functions and the functions the `main_thread` harness lists, and fails, naming each, on (a) a body with no check — a check is `assert…!`, `bail!`, `ensure!`, `panic!`, `.unwrap()`, `.expect(`, `unwrap_err`, `?`, a mock expectation `.expect_…(`, `#[should_panic]`, or a call of a helper named `assert_…`, `expect_…` or `check_…`; (b) a `return` before the first check; (c) the text `GATED:` in a test file outside `e2e-test/src/scenario_filter/`. The function-level parse is a brace-depth scan, enough for test code that `rustfmt` formats. The tests it finds today get a real check or go: `focus_macos::should_answer_without_panicking` (accepts every answer) checks that an `Err` names the AX error and an `Ok(Some)` a role, and that without Accessibility the answer is the error (the permission probe tells which); the four `visualfeedback_macos` functions without an assertion check the pill visibility and the generation they change, or go when they repeat a test that does; `ptt_rdev`, `soundplaying_macos` and the sound player's unit tests check the result they return; `recording_failure` and `archiving` assert on the doubles they hold. `recording_filesystem`'s two `VOICEPUNCHER_TEST_WAV` tests go: `should_return_buffer_with_correct_sample_count` already loads a WAV it writes itself.

**D5 — The paste tests use a pasteboard of their own.** `MacOsTextPaster` takes the pasteboard it writes by name (`with_pasteboard(name)`; the app keeps the general pasteboard); the adapter's `pasteboard` functions take the pasteboard instead of reading `NSPasteboard::generalPasteboard()`. The tests make one with `NSPasteboard::pasteboardWithUniqueName`, release it at the end, and no longer save and restore the user's clipboard; the machine-wide `PasteboardLock` and its test go, as nothing shares a pasteboard any more.

**D6 — Crate `test-steps`: the shared steps and test helpers.** A new workspace member `test-steps/` (`voicepuncher-test-steps`, a dev-dependency of `app`, `command-spotting` and `e2e-test`) holds `required_env` (D2) and the step texts both harnesses use. Their meaning is a trait, `SharedSteps`, one async method per step with its doc comment; a macro `shared_steps!(World)` expands, in the harness that calls it, into the `#[given]`, `#[when]`, `#[then]` functions with the texts, each calling the world's method. Each harness implements the trait in its own terms (doubles in-process, the real app and services in E2E) and deletes its own definitions of those texts; a method a level cannot perform returns an error naming the level. The 14 texts both define today are the trait's methods; "the overlay is hidden" as a Given becomes a check in both harnesses (the slice one was a no-op). The architecture rule gains (d): a step text literal in both `app/tests/steps/` and `e2e-test/tests/steps/` fails. Rejected: constants for the texts (cucumber's attributes take literals only); distinct texts per harness (the user chose the shared crate).

**D7 — Docs.** `AGENTS.md`: the layout lists `test-steps/`; § How to verify a change states the needs, the skip lines, `it-real` in `full-check` and in the manual run, and `test-real-keyboard` for the key presses; the stage table and `full_check_model_stages` self-test include `it-real`.

## Test levels

| Scenario | Level |
|---|---|
| The unit run leaves out the tests that need the services and says so | justfile self-test `_test-gates` (closed needs: exclusion and skip lines) |
| A model stage runs the tests that need the services it started | justfile self-test `_test-gates` (open needs: no exclusion); the model stages of `check` |
| A test run without its need fails and names it | unit (`test-steps`: `required_env` panics naming the variable and the recipe) |
| Missing user recordings leave the recording tests out with a count | justfile self-test `_test-gates` (`needs_voice_samples` closed) |
| The full check runs the desktop tests with the permissions granted | `just it-real` run once at stage 5; stage-table self-test (`it-real` in `full_check_model_stages`) |
| A missing permission skips the desktop stage and names it | justfile self-test of `_stages` (a stage exiting 77: skipped row, journal `skipped`, no pass) |
| Key presses into the focused app stay out of the full check | justfile self-test (`full_check_model_stages` and `_it-real`'s filter exclude `needs_real_keyboard`) |
| A test without a check fails the architecture tests | architecture (`test_checks` on a fixture source) |
| An early return before the first check fails the architecture tests | architecture (`test_checks` on a fixture source) |
| The paste tests run while the user has copied something | adapter integration (`textpasting_macos`: the general pasteboard's change count is unchanged) |
| A step text defined in both harnesses fails the architecture tests | architecture (shared step texts rule on a fixture pair) |

## Risks / Trade-offs

- [The brace scan misreads a test] → test code is rustfmt-formatted; the rule names the function, and a false hit is fixed by adding the check it asks for.
- [`it-real` pops windows during `full-check`] → it runs in the exclusive phase, the windows close themselves, and the stage takes seconds.
- [`cargo nextest list` per closed need costs time] → one list call per recipe with all closed needs' filter, split by need in the output.
